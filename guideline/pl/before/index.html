Zanim przyjdziesz

Dziewięćdziesiąt minut, trzydzieści osób, jedna pętla. Agent dostaje design, pisze stronę, a potem program — nie on sam — mówi mu wszystko, co jest z nią nie tak. Agent to poprawia i słyszy to jeszcze raz.

Ta strona to przygotowanie. Zajmuje około trzydziestu minut, idzie dużo lepiej w domu niż na konferencyjnym wifi i kończy się tym, że agent mówi ci, czy jesteś gotowy.

Około trzydziestu minut, od góry do dołu: cztery konta, kilka narzędzi, logowanie, własne repozytorium — a na końcu agent sprawdza całość i mówi, czego brakuje. Zrób to w domu. Na sali będzie trzydzieści osób i jedno wifi, a instalator to marny sposób na spędzenie pierwszych dwudziestu minut warsztatu.

Nie musisz umieć programować. Ta sesja jest zrobiona dla projektantów i ludzi od produktu. Każda komenda na tej stronie ma przycisk do kopiowania: kopiujesz, wklejasz do terminala, naciskasz Enter i czekasz, aż się skończy, zanim wkleisz następną.

Co będziemy budować

Agent pisze stronę. Program — nie agent — sprawdza ją względem designu, reguł kontrastu i tekstów, po czym spisuje, co jest nie tak. Agent to czyta i poprawia. I w kółko, aż program nie ma już nic do powiedzenia, a wtedy strona idzie na serwer.

Ciekawe jest to pudełko, które odmawia. Wszystko poniżej to rzeczy, których potrzebujesz, żeby w środę zbudować taką pętlę samodzielnie.

Otwórz terminal

Jeśli nigdy go nie otwierałeś, to jest ten moment, w którym ludzie odpadają — i odpadają, zanim w ogóle zaczną. To dwa kroki i nie jest niebezpieczne.

Terminal to okno, w którym wpisujesz nazwę programu, naciskasz Enter, a on wypisuje odpowiedź jako tekst. npm install i przycisk z napisem Instaluj robią dokładnie to samo — jedno wywołujesz nazwą, drugie kliknięciem.

Jak otworzyć terminal na macOS

  1. Naciśnij Cmd + Spacja.
  2. Wpisz Terminal.
  3. Naciśnij Enter.

Otworzy się okno z linijką tekstu i migającym kursorem. To wszystko. Wklejasz do niego przez Cmd + V.

Jak otworzyć terminal na Windows

  1. Naciśnij klawisz Windows.
  2. Wpisz PowerShell.
  3. Kliknij Windows PowerShell — nie „Wiersz polecenia", który wygląda podobnie i zachowuje się inaczej.

Otworzy się niebieskie okno z linijką tekstu i migającym kursorem. To wszystko. Wklejasz przez Ctrl + V albo prawym przyciskiem myszy.

Jak otworzyć terminal na Linuksie

  1. Naciśnij Ctrl + Alt + T.
  2. Jeśli nic się nie stanie, otwórz menu aplikacji i poszukaj Terminal.

Wklejasz przez Ctrl + Shift + V — samo Ctrl + V znaczy w terminalu coś innego.

Sześć rzeczy, których nikt nie mówi

Linijka z kursorem to prompt. Kończy się na $, % albo > i oznacza, że terminal czeka na ciebie.
Wklej, potem naciśnij Enter. Nic się nie uruchomi, dopóki tego nie zrobisz.
Cisza jest normalna. Komenda potrafi stać przez minutę i nic nie wypisywać. Nie zawiesiła się — pracuje. Nauczysz się czekać.
Skończyła się, kiedy wraca prompt. To jedyny sygnał, jaki dostajesz.
To, co przewinęło się do góry, jest zapisem. Nie da się kliknąć w starą linijkę i jej poprawić. Żyje tylko ta, którą właśnie piszesz.
Niczym z tej strony nie zepsujesz komputera. Każda komenda tutaj coś instaluje, loguje cię albo wypisuje, co znalazła.

Zainstaluj narzędzia

Cztery rzeczy: Node, który uruchamia stronę na twoim komputerze; Git i GitHub w terminalu, które trzymają projekt w repozytorium; jeden agent do kodu; i Netlify w terminalu, które publikuje stronę. Skopiuj każdą komendę, wklej do terminala, naciśnij Enter i poczekaj, aż wróci prompt, zanim przejdziesz do następnej.

Node, Git i GitHub w terminalu, na macOS

brew install node gh

To wymaga Homebrew. Nie masz? Najpierw wklej jedną komendę ze strony brew.sh — zapyta o hasło do Maca, a przy wpisywaniu nic się nie pokazuje i tak ma być. Git przychodzi razem z nim. Kiedy wszystko się skończy, zamknij terminal i otwórz nowy.

Node, Git i GitHub w terminalu, na Windows

winget install --id OpenJS.NodeJS.LTS
winget install --id Git.Git
winget install --id GitHub.cli
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

Po jednej. Ostatnia pozwala PowerShellowi uruchamiać narzędzia, które instalujesz dalej — bez niej npm i agent zatrzymają się na running scripts is disabled on this system. Jeśli zapyta, wpisz Y i naciśnij Enter. Potem zamknij PowerShell i otwórz nowy: nowe programy zauważa tylko przy starcie.

Node, Git i GitHub w terminalu, na Linuksie

sudo apt install -y curl git gh
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.7/install.sh | bash
nvm install --lts

Przed trzecią komendą zamknij terminal i otwórz nowy. Pierwsza zapyta o hasło; przy wpisywaniu nic się nie pokazuje i tak ma być. Node idzie przez nvm, bo większość dystrybucji ma starszy, niż potrzeba, i dlatego, że instalacje poniżej nie wymagają wtedy sudo. Nie Ubuntu ani Debian? Zainstaluj curl, git i gh swoim menedżerem paczek — instrukcja dla gh.

Zaloguj się

Każde narzędzie musi wiedzieć, kim jesteś, i każde robi to tak samo: komenda otwiera przeglądarkę, klikasz zgodę i wracasz do terminala. Potem jedna komenda pokazuje, że się udało.

GitHub

gh auth login

Zada kilka pytań; poruszasz się strzałkami, zatwierdzasz Enterem. Wybierz GitHub.com, potem HTTPS, potem Yes przy logowaniu Gita, potem Login with a web browser. Pokaże jednorazowy kod: naciśnij Enter, wklej kod w przeglądarce i kliknij Authorize.

Sprawdź:

gh auth status
mówi Logged in to github.com

Twój agent

Claude Pro albo Max

claude auth login

Przeglądarka otworzy claude.ai. Zaloguj się i kliknij Authorize. Jeśli terminal zamiast tego poprosi o kod, skopiuj go z przeglądarki i wklej z powrotem.

Sprawdź:

claude auth status
pokazuje "loggedIn": true

ChatGPT Plus

codex login

Przeglądarka otworzy ChatGPT. Zaloguj się i zezwól. Terminal powie, kiedy skończy.

Sprawdź:

codex login status
mówi Logged in using ChatGPT

Netlify

netlify login

Przeglądarka otworzy stronę Netlify. Kliknij Authorize i wróć do terminala.

Sprawdź:

netlify status
pokazuje twój adres e-mail

Załóż repozytorium

Twój projekt potrzebuje domu na GitHubie. Jedna komenda zakłada repozytorium — prywatne, więc widzisz je tylko ty — i kładzie jego pustą kopię na twoim komputerze, w folderze turbine.

gh repo create turbine --private --clone
cd turbine

W tym folderze zaczyna się warsztat. W dniu warsztatu otwierasz terminal, wchodzisz do niego przez cd turbine i tam uruchamiasz agenta. Do tego czasu zostaw go pustym.

Sprawdź:

git remote -v
pokazuje github.com/twoja-nazwa/turbine

Masz już repozytorium o nazwie turbine? Wybierz inną nazwę i używaj jej wszędzie, gdzie ta strona mówi turbine.

Niech agent sprawdzi wszystko

Ostatni krok i nie musisz niczego sprawdzać sam. Agent przegląda wszystko powyżej i mówi ci po ludzku, czego jeszcze brakuje.

  1. W terminalu wejdź do folderu projektu:
    cd turbine
  2. Uruchom agenta — claude albo codex. Jeśli zapyta, czy ufasz temu folderowi, odpowiedz tak.
  3. Skopiuj prompt poniżej, wklej go i naciśnij Enter.
Wklej to agentowi 
Przygotowuję się do warsztatu i mało pracowałem w terminalu. Sprawdź, czy ten komputer
jest do niego gotowy. Niczego sam nie instaluj, nie loguj się i niczego nie zmieniaj: tylko
patrz, i uruchamiaj takie komendy, jakich do tego potrzebujesz.

Sprawdź każdą z tych rzeczy i pokaż mi wynik jako tabelę — co sprawdziłeś, co znalazłeś,
i OK albo NIE OK:

1. Node jest zainstalowany, w wersji 20.11 albo nowszej, i npm działa.
2. Git jest zainstalowany i zna imię oraz adres e-mail, które wpisuje do commitów.
3. GitHub w terminalu (gh) jest zainstalowany i zalogowany.
4. Netlify w terminalu jest zainstalowany i zalogowany.
5. Ty, agent, z którym rozmawiam, jesteś zainstalowany i zalogowany. Powiedz, którym agentem
   jesteś.
6. Ten folder jest repozytorium git połączonym z repozytorium na GitHubie, to repozytorium
   istnieje i należy do konta, na które zalogowany jest gh.
7. Ten folder jest pusty, poza plikami samego gita. Warsztat zaczyna się od zera.

Przy każdym NIE OK napisz w jednym, dwóch zdaniach, po ludzku, co mam zrobić — z dokładną
komendą do wpisania, jeśli taka jest. Na końcu, w osobnej linijce: GOTOWE albo NIEGOTOWE
i ile rzeczy zostało.

Przed każdą komendą zapyta o zgodę. Zgadzaj się — tylko patrzy. Popraw to, co oznaczy jako NIE OK, i wklej ten sam prompt jeszcze raz, aż powie GOTOWE. Jeśli agent w ogóle się nie uruchamia, wróć do sekcji Zaloguj się.

Jeśli instalacja nie wchodzi w grę

Część służbowych laptopów nie pozwoli zainstalować niczego. Cały warsztat możesz wtedy zrobić w przeglądarce, w GitHub Codespace: komputerze w chmurze, który ma już Node, Gita i GitHuba w terminalu, i jest już zalogowany do GitHuba.

  1. Na github.com kliknij + → New repository. Nazwij je turbine, wybierz Private, zaznacz Add a README file — codespace nie otworzy się na pustym repozytorium — i kliknij Create repository.
  2. Na stronie repozytorium: Code → Codespaces → Create codespace on main. Trwa to minutę, dwie. Panel na dole to terminal, już w folderze repozytorium.
  3. Usuń README, żeby folder zaczynał pusty:
    rm README.md
  4. Zainstaluj agenta i Netlify — komendy z sekcji Zainstaluj narzędzia, od agenta w dół. Node, Git i GitHub już tam są.
  5. Zaloguj się do agenta i do Netlify jak w sekcji Zaloguj się. Terminal zamiast otwierać przeglądarkę wypisze link: przytrzymaj Ctrl albo Cmd i kliknij go. Codex potrzebuje logowania, które działa z innego urządzenia:
    codex login --device-auth

    Jeśli Codex powie, że logowanie kodem urządzenia nie jest włączone, włącz je w ChatGPT → Settings → Security i uruchom komendę jeszcze raz.

  6. Zrób krok Niech agent sprawdzi wszystko w terminalu codespace’a. Jesteś już w folderze projektu, więc pomiń cd turbine.

Darmowy plan GitHuba obejmuje 120 rdzeniogodzin Codespaces miesięcznie. Warsztat zużywa około trzech. W dniu warsztatu otwórz ten sam codespace z github.com/codespaces.

Pytania, które ludzie zadają

Nigdy nie używałem terminala.

Dobrze — jedna trzecia sali też nie. Jest o tym osobna sekcja wyżej, każda komenda ma przycisk do kopiowania, a pierwsze, o co na warsztacie poprosisz agenta, to żeby tłumaczył każdą komendę na bieżąco.

Czy muszę umieć programować?

Nie. Będziesz oglądać to, co zrobił agent, i mówić po ludzku, co jest nie tak. Dokładnie o tej robocie jest ta sesja.

Nie chcę płacić za subskrypcję AI.

Darmowe plany obu produktów nie obejmują narzędzia w terminalu, więc na darmowym koncie pętla nie ruszy. Najtańszy plan któregokolwiek wystarczy, a potem można zrezygnować.

Po co mi repozytorium na GitHubie?

To dom twojego projektu. Agent może zapisywać tam pracę na bieżąco, więc nic nie przepadnie, jeśli laptop odmówi posłuszeństwa, a z warsztatu wychodzisz z kodem, nie tylko z adresem.

Mam darmową Figmę.

To wszystko, czego potrzebujesz. Zapisujesz plik z Figmy — dwa kliknięcia — i dajesz go agentowi. Nic w warsztacie nie wymaga płatnego miejsca.

Sprawdzenie mówi NIE OK i nie rozumiem dlaczego.

Zapytaj agenta. Napisz „wytłumacz punkt 3, jakbym robił to pierwszy raz" — on wie, co znalazł. Jeśli dalej stoi, przyjdź na salę piętnaście minut wcześniej.

Czy na warsztacie będę potrzebować internetu?

Tak, i na sali on jest. Agent instaluje paczki, rozkodowuje plik Figmy i publikuje twoją stronę — wszystko to idzie przez sieć. Jeśli Codex zapyta o dostęp do sieci, odpowiedz tak.

Służbowy laptop nie pozwala mi nic instalować.

Użyj Codespace, jak opisano wyżej. Na samym laptopie nie instalujesz niczego.

Czy to zadziała na Windows?

Tak. Używaj PowerShella, nie starego Wiersza polecenia. Reszta sesji jest identyczna.

Co zabieram do domu?

Działający adres w internecie, repozytorium z kodem i osiem promptów, które zadziałają w poniedziałek.

W dniu warsztatu

Weź ze sobą: laptopa, ładowarkę i słuchawki, jeśli lubisz przy nich pracować.

Przyjdź: piętnaście minut wcześniej, jeśli agent nie powiedział GOTOWE.

Wyjdziesz z: działającym adresem w internecie, repozytorium z kodem, stroną promptów, których użyjesz w poniedziałek, i dość konkretnym zdaniem na temat tego, kiedy ufać modelowi językowemu.
