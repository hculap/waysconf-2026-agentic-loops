Before you come

Ninety minutes, thirty people, one loop. A coding agent is handed a design, writes a website, and is then told by a program — not by itself — everything that is wrong with it. Then it fixes those things and is told again.

This page is the preparation. It takes about thirty minutes, goes much better at home than on conference wifi, and ends with your agent telling you whether you are ready.

About thirty minutes, top to bottom: four accounts, a few tools, signing in, your own repository — and at the end your agent checks the lot and tells you what is missing. Do it at home. The room has thirty people and one wifi network, and an installer is a miserable way to spend the first twenty minutes of a workshop.

You do not need to know how to code. This session is built for designers and product people. Every command on this page has a copy button: copy, paste into the terminal, press Enter, and wait for it to finish before the next one.

What we are going to build

An agent writes a page. A program — not the agent — checks it against the design, the contrast rules and the copy, and writes down what is wrong. The agent reads that and fixes it. Round and round until the program says nothing is wrong, and then it goes live.

The interesting box is the one that refuses. Everything below is what you need so you can build one of those on Wednesday.

Open a terminal

If you have never opened one, this is the part that stops people, and it stops them before they have started. It is two steps and it is not dangerous.

A terminal is a window where you type the name of a program, press Enter, and it prints the answer back as text. npm install and a button labelled Install do the same work — one is addressed by name, the other by clicking.

Opening a terminal on macOS

  1. Press Cmd + Space.
  2. Type Terminal.
  3. Press Enter.

A window opens with a line of text and a blinking cursor. That is it. Paste into it with Cmd + V.

Opening a terminal on Windows

  1. Press the Windows key.
  2. Type PowerShell.
  3. Click Windows PowerShell — not "Command Prompt", which looks similar and behaves differently.

A blue window opens with a line of text and a blinking cursor. That is it. Paste into it with Ctrl + V, or by right-clicking.

Opening a terminal on Linux

  1. Press Ctrl + Alt + T.
  2. If nothing happens, open your applications menu and search for Terminal.

Paste into it with Ctrl + Shift + V — the plain Ctrl + V means something else in a terminal.

Six things nobody tells you

The line with the cursor is the prompt. It ends in $, % or >, and it means the terminal is waiting for you.
Paste, then press Enter. Nothing runs until you do.
Silence is normal. A command can sit there for a minute printing nothing. It has not frozen — it is working. You will learn to wait.
It is finished when the prompt comes back. That is the only signal there is.
What has scrolled past is a transcript. You cannot click into an old line and fix it. Only the line you are typing now is live.
You cannot break your computer with anything on this page. Every command here installs something, signs you in, or prints what it finds.

Install the tools

Four things: Node, which runs the website on your machine; Git and the GitHub command line, which keep your project in a repository; one coding agent; and the Netlify command line, which publishes the site. Copy each command, paste it into the terminal, press Enter, and wait for the prompt to come back before the next one.

Node, Git and the GitHub command line, on macOS

brew install node gh

This needs Homebrew. No Homebrew? Paste the one command from brew.sh first — it asks for your Mac password, and nothing appears as you type it, which is normal. Git comes with it. When everything has finished, close the terminal and open a new one.

Node, Git and the GitHub command line, on Windows

winget install --id OpenJS.NodeJS.LTS
winget install --id Git.Git
winget install --id GitHub.cli
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

One at a time. The last one lets PowerShell start the tools you install next — without it, npm and your agent stop with running scripts is disabled on this system. If it asks, type Y and press Enter. Then close PowerShell and open a new one: it only notices new programs when it starts.

Node, Git and the GitHub command line, on Linux

sudo apt install -y curl git gh
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.7/install.sh | bash
nvm install --lts

Close the terminal and open a new one before the third command. The first asks for your password; nothing appears as you type it, which is normal. Node comes through nvm because most distributions ship one older than the workshop needs, and because the installs below then need no sudo. Not on Ubuntu or Debian? Install curl, git and gh with your own package manager — instructions for gh.

You need one of these two, not both. If you have a Claude subscription take the first; if you have ChatGPT Plus take the second.

ChatGPT Plus

The Netlify command line

This is what puts your site on the internet at the end of the workshop.

npm install -g netlify-cli

If a command says command not found straight after you installed it, close the terminal and open a new one. That fixes it nearly every time.

Sign in

Each tool needs to know who you are, and they all do it the same way: the command opens your browser, you click to allow it, and you come back to the terminal. Then one more command shows it worked.

GitHub

gh auth login

It asks a few questions; move with the arrow keys and press Enter. Choose GitHub.com, then HTTPS, then Yes to authenticating Git, then Login with a web browser. It shows a one-time code: press Enter, paste the code in the browser, and click Authorize.

Check:

gh auth status
says Logged in to github.com

Your agent

Claude Pro or Max

claude auth login

Your browser opens on claude.ai. Sign in and click Authorize. If the terminal asks for a code instead, copy it from the browser and paste it back.

Check:

claude auth status
shows "loggedIn": true

ChatGPT Plus

codex login

Your browser opens on ChatGPT. Sign in and allow it. The terminal says when it is done.

Check:

codex login status
says Logged in using ChatGPT

Netlify

netlify login

Your browser opens a Netlify page. Click Authorize, then come back to the terminal.

Check:

netlify status
shows your email address

Create your repository

Your project needs a home on GitHub. One command creates the repository — private, so only you can see it — and puts an empty copy on your computer, in a folder called turbine.

gh repo create turbine --private --clone
cd turbine

That folder is where the workshop starts. On the day you open a terminal, go into it with cd turbine, and start your agent there. Leave it empty until then.

Check:

git remote -v
shows github.com/your-name/turbine

Already have a repository called turbine? Pick another name, and use it wherever this page says turbine.

Let your agent check everything

Last step, and you do not have to check anything yourself. Your agent looks at everything above and tells you, in plain words, what is still missing.

  1. In a terminal, go into your project folder:
    cd turbine
  2. Start your agent — claude or codex. If it asks whether you trust this folder, say yes.
  3. Copy the prompt below, paste it, and press Enter.
Paste this to your agent 
I am getting ready for a workshop and I have not used a terminal much. Check that this
computer is set up for it. Do not install, sign in to or change anything yourself: only
look, and run whatever commands you need in order to look.

Check each of these, and show me the result as a table — what you checked, what you found,
and OK or NOT OK:

1. Node is installed, version 20.11 or newer, and npm works.
2. Git is installed, and knows a name and an email address to put on commits.
3. The GitHub command line is installed and signed in.
4. The Netlify command line is installed and signed in.
5. You, the agent I am talking to, are installed and signed in. Say which agent you are.
6. This folder is a git repository connected to a repository on GitHub, that repository
   exists, and it belongs to the account the GitHub command line is signed in as.
7. This folder is empty apart from git's own files. The workshop starts from nothing.

For every NOT OK, tell me in one or two sentences what to do, in plain words, with the exact
command to type if there is one. Finish with one line on its own: READY, or NOT READY and
how many things are left.

It asks before running each command. Say yes — it only looks. Fix whatever it marks NOT OK, then paste the same prompt again until it says READY. If your agent will not start at all, go back to Sign in.

If installing is not an option

Some work laptops will not let you install anything. You can do the whole workshop in the browser instead, in a GitHub Codespace: a computer in the cloud that already has Node, Git and the GitHub command line, and is already signed in to GitHub.

  1. On github.com, click + → New repository. Name it turbine, choose Private, tick Add a README file — a codespace cannot open on an empty repository — and click Create repository.
  2. On the repository page: Code → Codespaces → Create codespace on main. It takes a minute or two. The panel along the bottom is a terminal, already in your repository folder.
  3. Remove the README, so the folder starts empty:
    rm README.md
  4. Install your agent and the Netlify command line — the commands from Install the tools, from the agent onwards. Node, Git and GitHub are already there.
  5. Sign in to your agent and to Netlify as in Sign in. The terminal prints a link instead of opening your browser: hold Ctrl or Cmd and click it. Codex needs the version of its login that works from another device:
    codex login --device-auth

    If Codex says device code login is not enabled, turn it on in ChatGPT → Settings → Security, then run it again.

  6. Run Let your agent check everything, in the codespace terminal. You are already in the project folder, so skip cd turbine.

GitHub’s free plan includes 120 core-hours of Codespaces a month. The workshop uses about three. On the day, open the same codespace from github.com/codespaces.

Questions people ask

I have never used a terminal.

Good — a third of the room has not either. There is a section on it above, every command has a copy button, and the first thing your agent is asked to do in the workshop is explain each command as it goes.

Do I need to know how to code?

No. You will read what the agent made and say what is wrong with it in plain English. That is the job the session is about.

I do not want to pay for an AI subscription.

The free tiers of both products do not include the command-line tool, so a free account will not run the loop. The cheapest tier of either is enough, and you can cancel afterwards.

Why do I need a GitHub repository?

It is where your project lives. Your agent can save its work there as it goes, so nothing is lost if a laptop gives up, and you leave with the code as well as the address.

My Figma is free.

That is all you need. You save the file out of Figma — two clicks — and hand it to your agent. Nothing in the workshop needs a paid seat.

The check says NOT OK and I do not understand why.

Ask it. Type "explain point 3 like I have never done this" — it knows what it found. If it is still stuck, bring it to the room fifteen minutes early.

Will I need the internet during the workshop?

Yes, and the room has it. Your agent installs packages, decodes the Figma file and publishes your site, and all three go over the network. If Codex asks before going online, say yes.

My work laptop will not let me install things.

Use a Codespace, as described above. You install nothing on the laptop itself.

Will this work on Windows?

Yes. Use PowerShell rather than the old Command Prompt. Everything in the session is the same.

What do I take home?

A live address, your repository with the code in it, and eight prompts that work on Monday.

On the day

Bring: your laptop, your charger, and headphones if you like working with them.

Arrive: fifteen minutes early if your agent did not say READY.

You will leave with: a live address, your repository with the code in it, a page of prompts you can reuse on Monday, and a fairly specific opinion about when to trust a language model.
