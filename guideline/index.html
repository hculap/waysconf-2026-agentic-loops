Build an AI that checks and fixes its own work

Agentic loops in practice

Ninety minutes, thirty people, one loop. A coding agent is handed a design and a brief, writes a website, and is then told by a program — not by itself — everything that is wrong with it. Then it fixes those things and is told again. This page is the preparation for that, it takes about fifteen minutes, and it goes much better at home than on conference wifi.

You leave with a live URL for a site an agent built from a design, failed its own accessibility and design-token checks on, and repaired without being told how.

02 — Three steps, one of which you may already have done

Install on your machine

Node, then the agent of your choice, then one line that proves both worked. Pick your operating system. Every command below can be copied.

You can skip this entire section. The browser route runs the whole workshop inside a GitHub tab with nothing installed on your laptop, and it is a first-class path rather than a consolation prize. If your machine fights you for more than ten minutes, stop and take that route instead.

macOS

  1. Install Node 20.11 or newer

    Two ways, and neither is better. Without a terminal: download the macOS installer marked LTS from nodejs.org and double-click it. With Homebrew, if you already have it:

    Terminal 
    brew install node

    Open Terminal with Command + Space, type Terminal, press Enter. It is a box you type one line into. Nothing you run from this page can damage anything.

  2. Install the agent you chose

    One of these two. Not both.

    Claude Pro or Max 
    npm install -g @anthropic-ai/claude-code
    ChatGPT Plus or Pro 
    npm install -g @openai/codex

    The first time you run either one it opens a browser to sign you in. Do that once now, not at 14:55.

  3. Check it worked

    One line. It prints four version numbers and stops at the first thing that is missing.

    Terminal 
    node -v && npm -v && git --version && claude --version

    On Codex, end the line with codex --version instead. If git is the thing missing, macOS offers to install the developer tools: accept, wait, run the line again. Expected output is in the self-test.

Windows

  1. Install Node 20.11 or newer, and git

    Open PowerShell: press the Windows key, type PowerShell, press Enter. Then run these two lines, one at a time.

    PowerShell 
    winget install OpenJS.NodeJS.LTS
winget install Git.Git

    No winget, or it refuses? Download the LTS installer for Windows from nodejs.org and run it, then git from git-scm.com. Then close PowerShell and open it again. This is the step people miss: until the window is reopened, Windows will keep saying node is not recognized.

  2. Install the agent you chose

    One of these two. Not both.

    Claude Pro or Max 
    npm install -g @anthropic-ai/claude-code
    ChatGPT Plus or Pro 
    npm install -g @openai/codex

    Both run in PowerShell. The Codex CLI is best supported under WSL2, so if you are on ChatGPT and Windows and anything behaves strangely, do not spend your morning on it — the browser route is shorter than installing WSL.

  3. Check it worked

    PowerShell separates commands with a semicolon, so this line is slightly different from the one on macOS and Linux.

    PowerShell 
    node -v; npm -v; git --version; claude --version

    On Codex, end the line with codex --version instead. Expected output is in the self-test.

Linux

  1. Install Node 20.11 or newer

    Check what you have first with node -v. Distribution packages are often older than 20.11, which is the one version number that matters here.

    Debian and Ubuntu 
    curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt-get install -y nodejs git
    Fedora 
    sudo dnf install -y nodejs npm git
    Arch 
    sudo pacman -S --needed nodejs npm git

  2. Install the agent you chose

    Point npm at a directory you own first, so that a global install needs no sudo and nothing lands in system directories.

    Once, before installing 
    mkdir -p ~/.npm-global && npm config set prefix ~/.npm-global
echo 'export PATH="$HOME/.npm-global/bin:$PATH"' >> ~/.profile
source ~/.profile

    Then one of these two. Not both.

    Claude Pro or Max 
    npm install -g @anthropic-ai/claude-code
    ChatGPT Plus or Pro 
    npm install -g @openai/codex

  3. Check it worked

    Terminal 
    node -v && npm -v && git --version && claude --version

    On Codex, end the line with codex --version instead. Expected output is in the self-test.

Then, if you have ten more minutes

This is the best possible use of your home wifi, because it is a few hundred megabytes and the room has thirty people on one network. Take your own copy of the repository from github.com/hculap/waysconf-2026-agentic-loops with Use this template → Create a new repository, then:

Terminal or PowerShell 
git clone https://github.com/YOUR-USERNAME/my-turbine.git
cd my-turbine
npm install
npx playwright install chromium

Replace YOUR-USERNAME with yours. If you have the GitHub CLI, the copy and the clone are one line: gh repo create my-turbine --template hculap/waysconf-2026-agentic-loops --public --clone. Either way you end up in the same place, and you arrive on Wednesday with nothing left to download.

03 — Nothing installed, nothing to undo

Or skip all of that

GitHub Codespaces gives you the whole environment in a browser tab: Node, the project, the browser the tests drive, and both agent CLIs, all installed before you arrive. Several people take this route every time it is run, and nothing in the workshop is unavailable there.

  1. Open the repository

    github.com/hculap/waysconf-2026-agentic-loops, signed in with the GitHub account from step 01.

  2. Click “Use this template”, then “Create a new repository”

    The button is green, at the top right of the file list. This gives you your own copy to break.

  3. Name it, then click “Create repository”

    my-turbine is a fine name. Public or private both work; Codespaces and Netlify do not care which you pick.

  4. On your new repository: Code → Codespaces → Create codespace on main

    The green Code button, then the Codespaces tab next to Local, then Create codespace on main. A new tab opens with an editor in it.

  5. Wait about three minutes for the first boot

    It installs the project, the Chromium build the checks drive, and both agent CLIs. It only does this once. The terminal prints Environment ready. when it is done.

  6. Prove it works

    In the terminal at the bottom of that tab:

    Codespaces terminal 
    npm run dev

    A notification offers Open in Browser. Click it. You get the starter page, which is deliberately almost empty — that is what the workshop fills in. Stop the server with Ctrl + C.

What it costs, with the arithmetic

Nothing, and you are not close to the edge. A free GitHub account includes 120 core-hours of Codespaces per month. This project asks for the 2-core machine, which spends two core-hours for every hour it is running. The workshop is ninety minutes, so it costs you three core-hours — about two and a half per cent of the month. You would have to leave it running for sixty hours to exhaust the allowance.

Storage counts separately and is also free at this size. The codespace stops itself after thirty minutes of inactivity, and you can delete it outright from github.com/codespaces when the workshop ends.

What you give up, honestly

It is someone else’s computer, and the editor is VS Code in a browser tab: your own key bindings, extensions and fonts are not there, and a poor connection means a laggy editor. The first boot is three minutes you do not spend if Node is already on your laptop.

What you do not give up is any part of the workshop. Same repository, same checks, same loop, same deploy, same URL at the end.

Take this route if

Your laptop is managed by your employer and you cannot install software. You are on Windows without WSL. Your Node install did not work within ten minutes. Or you would simply rather spend ninety minutes watching a loop repair a website than debugging a PATH variable, which is a completely reasonable preference and the reason this route was built first.

04 — Confirm it, do not assume it

Am I ready?

Run these in a terminal — yours, or the one in your codespace — and compare what comes back. Version numbers will differ from ours; the shape of the answer should not. The last one is supposed to fail.

  1. Type this
    Node 
    node -v
    You should see v22.22.3

    Anything from v20.11.0 upwards is fine. If it says v18 or command not found, Node is the one thing to fix.

  2. Type this
    npm 
    npm -v
    You should see 10.9.8

    Any 10.x or 11.x. It arrives with Node; you never install it separately.

  3. Type this
    git 
    git --version
    You should see git version 2.43.0

    Any 2.x. Not needed at all on the browser route.

  4. Type this, if you chose Claude
    Claude Code 
    claude --version
    You should see 2.1.268 (Claude Code)

    Any 2.x. Then run claude once on its own: it opens a browser, you sign in, and it never asks again. Do that before Wednesday.

  5. Type this, if you chose ChatGPT
    Codex CLI 
    codex --version
    You should see codex-cli 0.153.4

    Then run codex once on its own and sign in the same way. One of these two lines applies to you, not both.

  6. Type this
    Netlify 
    npx netlify --version
    You should see netlify-cli/26.0.2 linux-arm64 node-v22.22.3

    Your operating system and processor will read differently; the version at the front is the part that matters. The first run asks permission to download the CLI. Say yes.

  7. Last one, inside your copy of the project
    Terminal or PowerShell 
    npm run check
    You should see it fail a long list of failures, and a non-zero exit

    This one is meant to go red. Nothing has been built yet, so every gate has something to complain about, and those complaints are the workshop’s task list. If this prints failures, your setup is correct and you are completely ready.

If a line does not match, the questions below probably cover it. If they do not, write to us and paste what it actually printed. “It does not work” cannot be answered from here; node -v printing v18.19.0 can be answered in one sentence.

05 — The ones people actually ask

Questions

Asked by people who came to earlier runs of this, answered the way they were answered then.

I have never used a terminal

Neither had most of the room last time. A terminal is a box where you type one line and press Enter, and the computer answers. You will type perhaps eight lines in ninety minutes, every one of them is on this page or on a slide, and you can paste all of them.

Nothing here deletes files, changes your system settings or needs an administrator. If you would still rather not have one on your own laptop, the browser route gives you a terminal inside a tab that you can throw away afterwards.

Do I need to know how to code?

No. The agent writes the code. What the workshop actually asks of you is to decide what “correct” means precisely enough that a program can check it — which is a design and research skill, not a programming one.

In practice the developers in the room finish the code faster and the acceptance criteria slower. Writing a criterion that a machine can decide, spotting the one that no machine can, and noticing the requirement the agent quietly dropped: that is the part that transfers to your Monday, and it has nothing to do with syntax.

I do not want to pay for an AI subscription

Understood, and here is the honest position: one paid plan, or an API key with credit on it, is the only cost on this page, and without one the agent has nothing to run on.

Three ways around it, in the order they usually work. Pair with someone — two people per laptop is genuinely a better workshop, because the arguments about what the criteria should say are the good part. Use a plan you already have through work. Or start a monthly plan the day before and cancel it on Thursday; both are about 20 USD and both cancel in two clicks.

If none of that works, come anyway. Nobody is turned away, you will pair with someone who has one, and you still leave with the repository, the slides and every prompt.

My Figma is free

That is enough, and it is not a compromise. The TURBINE design is committed to the repository twice over: as full-page exports at 390, 768 and 1440 pixels, and as a token file naming every colour, space, radius and type size. The check that compares your build to the design reads those files, so the free path is the reference path.

What a paid seat adds is Figma’s Dev Mode, which lets the agent read the live file through an MCP server. It is a nicer way in. It is not required, and its absence blocks nothing. There is also a route that works on a free account using a personal access token; loop/MCP.md in the repository has the commands and is honest about what each route does and does not give you.

What if my laptop is locked down by my employer?

Then do not fight it in the room. If you can reach github.com in a browser and sign in, the browser route needs nothing else: no install, no administrator rights, no PATH, no antivirus exception. That is precisely what it is there for.

Two things worth testing this week, from the machine you will actually bring: that github.com and github.dev both open, and that your network does not block the browser sign-in for Claude or ChatGPT. Both take a minute now and cannot be fixed at 14:55.

Will this work on Windows?

Yes. Node, git and both agent CLIs install and run in PowerShell, and the install section gives every command in PowerShell form.

Two Windows-specific things. Close and reopen the terminal after installing Node, or it will keep insisting node is not recognized when Node is right there. And the Codex CLI is best supported under WSL2 — so if you are on ChatGPT and Windows and something is strange, take the browser route rather than installing WSL on a Tuesday night. Windows is the one platform where we would suggest Codespaces first.

What if I fall behind?

Every stage of the workshop is a branch in the repository, so one command puts you exactly where the room is, with everything up to that point already done.

Terminal or PowerShell 
git checkout step-3

Nobody is stuck for more than one section. And there is nothing to catch up on afterwards: the repository you leave with contains the finished state of every stage.

What do I take home?

A public URL for a site an agent built and repaired, and your own copy of the repository: nine automated checks, the twelve-line loop script, every prompt used on stage, the slides, and a record of what happened when this was run end to end before the conference, including the parts that went wrong.

The part that transfers is the shape, not the festival: one artifact, one program that returns pass or fail without consulting a model, and a loop that stops on an exit code. docs/TIPS.md ends with five places to start in your own work, each smaller than this workshop and the same shape.

Which of the two agents should I pick?

The one you already pay for. If you pay for neither, either is a fine choice: Claude Code is what is on the screen at the front, so following along is fractionally easier, and the Codex CLI runs the same prompts through the same loop with one word changed in the command.

Nothing in the workshop depends on the choice, and both are named in the repository’s own documentation rather than one being the real path and the other a footnote.

Do I need to install anything if I use Codespaces?

No. A browser and a GitHub login. Node, the project dependencies, the Chromium build the checks drive and both agent CLIs are installed by the container before you touch it. You still need your agent subscription, because that is an account rather than an install.

Does any of this send my work somewhere?

Your prompts, and the repository files the agent reads, go to whichever model provider you chose. That is what an agent is, and it is worth knowing rather than assuming.

Everything else stays with you: the checks run in a browser on your own machine or in your own codespace, the site is a folder of static files, and the deploy pushes that folder to your own Netlify account. There is no shared account, no telemetry and no analytics anywhere in the project. This setup page makes no network requests at all — the fonts are in the folder next to it.

Can I use Cursor, Copilot or something else instead?

Bring whatever you like in addition, but for the loop itself use one of the two named CLIs. The loop runs an agent from a shell script, unattended, and reads its exit code; those two do that in one line each.

An assistant inside an editor can do everything the workshop does by hand. What it cannot do is be put in a script that runs twelve times while you watch, and watching that is the point of the ninety minutes.

  2. Try the browser route

    It removes every category of problem on this page in about four minutes and needs nothing from your laptop. If you are reading this at 14:40 on Wednesday, do this and only this.

  3. Ask, with the output attached

    Send the output from step one, your operating system, and which of the two agents you chose. Or come to ROOM-PM at 14:45: we will be there, and the first ten minutes exist for exactly this.

About TURBINE

TURBINE is a fictional electronic music festival created as teaching material for this workshop. Artists, copy and imagery are invented. Any resemblance to a real event or performer is coincidental.

Colophon

One HTML file, three self-hosted faces and the festival’s own design/tokens/tokens.css, copied out of the repository unchanged. No framework, no build step, no cookies, no analytics, no request to anywhere. Your checklist ticks are stored by your browser and read by nobody.

One token from that file is deliberately unused here: color.text.muted, #6B7280. It measures 4.07:1 against this background and fails WCAG AA for body text. It exists in the TURBINE palette because a careless build reaches for it, the accessibility gate catches it for real, and the agent repairs it. That failure is the demonstration, so this page does not quietly commit it. — Code MIT, design and copy CC BY 4.0.
